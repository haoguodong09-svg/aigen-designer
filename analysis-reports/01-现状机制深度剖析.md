# 01 · 表单元素事件绑定/生命周期绑定 —— 现状机制深度剖析报告

> 分析对象：epic-designer fork（aigen-designer），工作区 D:/workspace/Github/epic-designer 分析范围：画布选中组件 → 右侧「事件」面板 → 动作配置弹窗 → schema.on 存储 → 运行时触发执行（事件 / 生命周期）的完整链路，及其 UX 痛点、能力边界、技术债。说明：所有行号证据均来自本工作区当前源码，引用格式为「文件路径:行号」。未标注行号处为「全仓检索无实现」的结论。

## 0. 核心结论摘要（Top5 痛点）

1. **设计态事件完全不触发、零运行反馈**：node.vue:369 在 isDesignMode 下不生成任何 onXxx 事件 prop，设计器（useDesigner.ts:128）又永远处于设计态 —— 用户绑完事件无法在画布验证，唯一出路是整页预览（preview/index.vue:124 全屏弹窗），而动作执行错误只进 console（pageManager.ts:267/283/332/391/400），用户毫无感知。
2. **「自定义函数」动作编辑的是整页 script，不是单个动作**：aigenScriptEdit.vue:26 的 v-model 直接绑定 pageSchema.script（整页全局脚本），在动作弹窗里改一行就影响全页所有动作，且无独立入参/出参/说明，用户完全无法理解“这个动作能做什么”。
3. **生命周期事件名是 Vue 内部术语**：event.vue:26-59 硬编码 vnodeMounted / vnodeUpdated / vnodeErrorCaptured / vnodeBeforeMount 等 8 个事件，用户看不懂何时触发、触发顺序如何，界面上无任何时机/顺序说明。
4. **动作弹窗是“开发式”布局且默认落到自定义函数**：1200px 大弹窗（aigenActionModal/index.vue:246）左侧“自定义函数/公共函数/组件树”+动作列表、右侧参数/脚本区；点「+」默认打开自定义函数类型（index.vue:124-132），要绑组件方法得先切“组件”再到树里找目标（index.vue:255-269），两步且概念绕。
5. **没有任何画布级的可视化绑定/反向查看**：全仓无“连线/关联”实现；大纲树只有布尔“事件”badge（outline.vue:102-107），看不到绑了哪些事件、指向哪些组件，无法回答“谁改了我的值”；动作项列表只显示 methodName 原始名（AigenActionEditorItem.vue:135）。

3. **事件面板组装事件列表**（event.vue）：

   - 通过 pluginManager.component.get('AigenActionEditor') 运行时查找子组件（12 行）；

### 2.3 存储结构：ActionsModel / ComponentSchema.on

packages/types/src/aigen-designer.ts：

- ActionsModel（9-14 行）：{ args?: string; componentId?: null|string; methodName: string; type: 'component'|'custom'|'public' } —— 扁平四字段，args 是 JSON 字符串。
- ComponentSchema.on（45-47 行）：{ [eventName: string]: ActionsModel[] } —— 事件名 → 动作数组，无描述、无来源、无状态。
- PageSchema.script（94 行）：整页自定义函数脚本字符串。
- ComponentSchema.show（54 行）：(RenderCallbackParams)=>boolean | boolean，支持函数式显隐。

配套类型（packages/types/src/pluginManager.ts）：EventModel（31-39 行，describe 已废弃）、ActionModel（41-44 行，含 argsConfigs?: ComponentSchema[]）、PublicMethodModel（93-114 行，无 argsConfigs）。

组件配置声明格式（以 packages/ui/antd/src/input/index.ts 为例）：

- config.event（128-149 行）：{ description: '输入值时', type: 'input' } 等 5 个事件 —— 事件名与底层 UI 库 emit 名**人工对齐**；
- config.action（7-20 行）：{ description: '使输入框获取焦点', type: 'focus' } 等 —— 与组件实际 exposed 方法**人工对齐**；
- 输入类组件在注册时由 useComponentManager.ts:308-383 自动注入 setValue（含 argsConfigs「设置数据」，320-331 行）、getValue（332-335 行）、setAttr（含 argsConfigs 动态属性列表，347-382 行）；form 组件声明 getData/setData/validate（form/index.ts:6-19），与 antd form.vue 实际 defineExpose（139-145 行）一致。

### 2.4 运行时：on → onXxx props → doActions → 实例方法/函数调用

**接线点（node.vue）**：

- getProps（366-409 行）核心片段（368-380 行）：

```ts
if (!pageManager.isDesignMode.value) {
  // 369 行：设计态不绑定，防误触发
  innerSchema.on &&
    Object.keys(innerSchema.on).forEach((item) => {
      onEvent[`on${capitalizeFirstLetter(item)}`] = (...args) =>
        pageManager.doActions(innerSchema.on![item], scopeName.value, ...args);

}
```

onXxx props 随 v-bind=getProps 传给实际组件（572 行）—— 组件事件（如 change）由 UI 库 emit，触发对应 onXxx prop，即进入 doActions。

- **组件实例注册**：handleAddComponentInstance（416-453 行），在 @vue:mounted（580 行）时执行；innerSchema.input 组件注入 exposed.setValue/getValue（432-436 行）、schema（438 行）、setAttr/getAttr（441-450 行）；卸载时 handleVnodeUnmounted（458-469 行，onBeforeUnmount 561 行）移除实例。

**doActions 执行链（pageManager.ts:260-337）**：

1. 空数组警告（266-269 行）；
2. 解析 action.args JSON（275-289 行），非法 JSON 仅跳过该动作并 console.warn（281-287 行）；无 args 时用事件原始载荷（289 行）；
3. 构造上下文 { event: args, formData: 单表单数据或表单集合 }（292-299 行）；
4. **表达式参数**：遍历参数，**isExpression** 标记的对象经 formulaEngine.calculate(arg.content, context) 求值（301-309 行）；
5. 按 type 分发（311-335 行）：
   - component → executeComponentMethod（380-405 行）：find(componentId) → component[methodName](...args)；找不到 console.warn（390-393 行），异常 console.error（398-404 行）；
   - custom → executeCustomMethod（361-372 行）：funcs.value[methodName]?.(...args)；
   - public → executePublicMethod（344-354 行）：publicMethods.methodsMap[methodName].handler(...args)。
6. **自定义函数编译**：setMethods（189-241 行）用 new Function('const aigen = this;' + script) 编译整页脚本，注入 defineExpose/find/findAll/findInstance/findInstanceAll/getComponent/pluginManager/publicMethods/state(=pluginManager.global)（221-232 行）；defineExpose（247-251 行）把函数写入 pageManager.funcs；watch(pageSchema.script) 自动重编译（456-464 行）。
7. **find/findAll**（56-80 行）：按 id 直查实例表 componentInstances，按其他字段（如 field/type）先 findSchemas 递归查 schema 再取实例（88-142 行）。

### 2.5 生命周期事件接线（aigenReady / vnodeMounted 等）

生命周期事件与组件事件**走完全不同的触发路径**：

| 事件名（event.vue:26-59） | 含义（面板文案） | 实际接线 |
| --- | --- | --- |
| aigenReady | 挂载完成（全部组件） | **Builder 特判**：builder.vue:144-154 handleReady（Suspense @resolve，203 行）watch mountMonitor.isAllMounted → triggerAigenReady（156-167 行）遍历**所有** schema 执行 schema.on.aigenReady 的 doActions（161-166 行） |
| vnodeMounted | 挂载完成（本组件） | node.vue:368-380 映射为 onVnodeMounted，Vue 运行时在根 vnode 挂载时自动调用（Vue 内置 vnode 生命周期钩子） |
| vnodeUpdated / vnodeBeforeMount / vnodeBeforeUpdate / vnodeBeforeUnmount / vnodeUnmounted / vnodeErrorCaptured | 更新/卸载/错误捕获等 | 同上，映射为 onVnodeXxx 系列 |

- **mountMonitor 机制**（useMountMonitor.ts）：pendingIds Set；node.vue:417-422 在组件 setup 时 push(id)、实际 UI 组件 vnode 挂载（@vue:mounted）时 pop(id)；isAllMounted = pendingIds.size === 0（第 9 行）。
- **注意**：所有生命周期事件同样受 node.vue:369 设计态守卫约束；aigenReady 的触发点 builder.vue 只在运行时 Builder（非设计器）里存在。设计器（useDesigner.ts:128 pageManager.setDesignMode()）中**所有事件一律不触发**。

### 2.6 设计态/运行态切换与「预览」

- 设计器永远 setDesignMode()（useDesigner.ts:128）→ 事件不绑定（node.vue:369）、script 编译错误不输出 console（pageManager.ts:460）、字段加 -design-mode 后缀（node.vue:182-194）、隐藏组件可显示（node.vue:255-257）。
- 「预览」＝ 头部按钮 → designer.vue:221 → preview/index.vue:58-62 深拷贝 pageSchema 快照 → 全屏 Modal 内挂一个**全新 AigenBuilder**（preview/index.vue:110-125）。这是用户**唯一**能验证事件绑定的途径。

### 3.2 重点痛点展开（与产品负责人抱怨直接对应）

**(1) “不知道如何在画布上快捷进行多元素之间的绑定”**

- 画布上没有任何绑定入口/手势/连线：选中组件后只能进右侧「事件」面板（rightSidebars/index.ts:23-28），且事件在**设计态不触发**（node.vue:369），用户无法就地验证；
- 动作弹窗里选目标组件靠**树**（index.vue:271-305），树里 label 与 id 并列、还要「复制ID」（287-302 行）——因为自定义函数只能 find('写死的id')（customFunctions.md:13），组件一删一建 id 就变，脚本即失效；
- 一个事件绑定多个动作只能靠顺序数组（ActionsModel[]），无并发/条件/延迟语义。

## 5. D. 技术债与扩展性评估

### 5.1 on 结构 / ActionsModel 的表达力

- **扁平四字段，表达力弱**：{args, componentId, methodName, type}（aigen-designer.ts:9-14）——无 condition、无 delay、无 if/else、无嵌套、无并行/串行语义、无错误处理字段。多步流程只能退化为“同一事件下多个动作顺序执行”（pageManager.ts:272 forEach）。
- **条件只能“算”不能“控”**：表达式（**isExpression**）可计算参数值（pageManager.ts:301-309），但**无法决定动作是否执行**；FormulaEngine.IF（formulaEngine.ts:21-22）只能当函数用。
- **事件名即语义**：on[eventName] 的键直接映射为 onXxx props（node.vue:371-379），事件描述只存在于组件 config（event.vue:72），schema 里没有；导出 JSON 后事件含义不可自解释。
- **若要支持 if/else、延迟、多步流程**：需要扩展 ActionsModel（如 condition/delay/children）并同步改造 doActions（pageManager.ts:260-337）与动作弹窗（aigenActionModal/index.vue）——属于破坏性 schema 变更，且旧数据（无这些字段）需兼容。

### 5.2 aigenActionModal 与事件面板的耦合

- **运行时组件查找链**：event.vue:12 → pluginManager.component.get('AigenActionEditor') → AigenActionEditor/index.vue:22 → pluginManager.component.get('aigenActionModal')。三者都注册在 panel-ui 包（components/index.ts:32-39），互相隐式依赖，脱离 panel-ui 即断链。
- **业务特判写死在 UI**：label === '设置数据' 替换 argsConfigs（index.vue:106-117）；methodName === 'setAttr' 特殊解析（index.vue:162-188）；默认 type='custom'（index.vue:127）。组件只要改个 label 或方法名，这些特判就静默失效——UI 与组件注册逻辑（useComponentManager.ts:308-383 注入“设置数据”标签）隐式契约，无类型/常量共享。
- **共享配置被运行时污染**：actionArgsConfigs computed 直接改写 pluginManager 里组件 config 的 argsConfigs（index.vue:106-117），而 componentConfigs 是**非响应式普通对象**（useComponentManager.ts:21）——改动静默、持久、影响后续所有编辑会话。

### 5.3 事件列表硬编码 / 三处来源不统一

- 事件来源有三个：① LIFECYCLE_EVENTS 常量（event.vue:26-59）；② 组件 config.event（event.vue:72）；③ aigenReady 在 builder 特判（builder.vue:161-166）。无统一“事件注册表”，组件无法声明自己的生命周期/特殊事件。
- 生命周期与组件事件同名冲突时（如某组件恰好有 vnodeMounted 事件）会重复展示/重复执行——无去重逻辑。

### 5.4 设计态与运行态隔离

- 设计态：isDesignMode=true（useDesigner.ts:128）→ 事件不绑定（node.vue:369）、script 编译错误不打印（pageManager.ts:460）、field 加 -design-mode 后缀（node.vue:182-194）。
- 运行态：预览 = 深拷贝快照 + 全新 AigenBuilder（preview/index.vue:58-62,124），与设计器完全隔离（不共享 pageManager/实例表）。
- 后果：**设计与验证之间隔着一道“预览”墙**，且预览是独立弹窗（900px），无法对照画布局部验证；这正是“一头雾水”的根源之一。

### 5.5 其他技术债

- **args 是 JSON 字符串**：类型松散，aigenArgsEditor.vue:14-19 无 JSON.parse 错误边界，非法数据直接抛错；handleSave 里 JSON.parse(state.actionItem.args)（index.vue:176）同样无保护。
- **双写路径**：事件面板 getValueByPath(selectedNode,'on') 直接取响应式引用（event.vue:98），AigenActionEditor 又直接写 modelValueComputed.value[item.type]（index.vue:56）与 emit update 并存，容易不一致。
- **演示残留**：methodName: 'test' 默认值（index.vue:33）。
- **兼容层堆积**：describe/method/methodName 等 deprecated 字段（types/pluginManager.ts:33,95-113；usePublicMethods.ts:24-45），切换 UI 库（antd/elementPlus/naiveUi）时事件名/动作名各自维护一份（如 input 的 config.event 三份），错配风险高。
- **文档缺失**：layoutGuide.md 空文件；无事件/动作操作手册，设计意图只散落在 customFunctions.md 与 updateLog.md（如 91 行“组件动作参数添加公式解析功能”、295 行“新增ready生命周期”）。
- **执行链不可观测**：doActions 无返回值/回调/事件，动作链无法被拦截、统计或打断（pageManager.ts:260-337）。

## 6. 附：改进方向建议（供后续方案设计参考，非本次范围）

1. **设计态可验证**：提供“设计态试运行”（临时切 isDesignMode=false 局部生效）或画布内“事件回放浮层”，把 console 错误提升为 UI 提示（toast）。
2. **动作模型升级**：ActionsModel 增加 condition/delay/name/description，为 if/else、延时执行、可读列表铺路（注意旧数据兼容）。
3. **单动作编辑器**：把“自定义函数”从整页 script 改为“动作=函数 + 参数模板”，或至少提供“新建动作脚手架”（自动生成函数骨架并 defineExpose）。
4. **友好命名**：生命周期事件名加中文别名与触发时机说明；动作项列表显示“目标组件+动作描述+参数摘要”而非 methodName。
5. **可视化关联**：画布提供“从事件源拖到目标组件”的绑定入口，并支持“反查谁绑定了我”。
6. **去耦合**：把“设置数据/setAttr”特判下沉为组件 config 的声明式元数据；事件来源统一注册表，移除 aigenReady 特判。
