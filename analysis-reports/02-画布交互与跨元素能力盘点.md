# 画布交互与多元素关联能力盘点报告

> 目标代码库：D:\workspace\Github\epic-designer（aigen-designer，epic-designer 的 fork）盘点范围：画布选择/悬浮/拖拽/右键交互、属性/样式/事件侧栏、动作配置弹窗、字段级编辑器、运行时联动能力（公式引擎、字段状态、事件总线、表格元数据）结论摘要：**事件/关联的唯一配置入口是"右侧事件面板 + 1200px 动作配置大弹窗"；画布元素上不存在任何事件/关联状态的可视化标记（全库唯一的"已绑定事件"角标在左侧"大纲"树里）；跨元素逻辑（值联动、显隐、禁用、计算）几乎全部依赖手写 JS 自定义函数 + 硬编码 componentId；多选与批量操作完全缺失。** 但底层能力（公式引擎、FieldState/condition、事件总线、useTableMeta）均已存在，只是没有暴露为可视化交互。

## C. 用户完成任务的心智成本分析（三个典型任务走查）

### C.1 任务 1：输入框 A 的值变化时，把 B 的值设为 A×2

当前 UI 路径：

1. 在画布点击 A → 选中（`editContainer/index.vue:43-65`）。
2. 右侧栏点击"事件"页签（`rightSidebars/index.ts:23-28` 注册的事件面板）。
3. 在"组件事件"折叠组里找到 A 的 `change`（值修改）事件 → 点右侧 ＋（`AigenActionEditorItem.vue:93-106`）。
4. 弹出 1200px 的"动作配置"弹窗（`aigenActionModal/index.vue:244-250`）：默认选"自定义函数"（`handleOpen` 强制 type='custom'，124-132），右侧出现 Monaco 编辑器（`aigenScriptEdit.vue:25-31`），**它直接编辑整个页面的 `pageSchema.script`**。
5. 用户必须写：
   ```js
   const { find } = this;
   function test(e) {
     find('B的id').setValue((find('A的id').getValue() ?? 0) * 2);
   }
   defineExpose({ test });
   ```
   （官方做法见 `examples/src/views/builder/sum/index.vue:86-87`）

认知障碍：

- **需要知道 componentId**：B 的 id 是机器生成的（`input_9620` 之类，见 fieldStates 示例），必须先在属性面板顶部复制 ID（`attribute.vue:61-76` 有"复制节点ID"按钮），再粘贴进脚本——心智上是"写代码"而非"配置"。
- **需要写 JS**：`find/getValue/setValue` API 属于开发者知识（`docs/guide/utils/pageManager.md:79-103`），还要知道 `??0` 防 NaN。
- **Monaco 编辑的是全局脚本**：`aigenScriptEdit.vue:26` `v-model="pageSchema.script"` —— 所有函数都塞进一个全局 script，函数名冲突、作用域混乱是隐忧；也没有"保存/应用"按钮，改动即时生效，用户难以感知边界。
- **必须 `defineExpose`** 才能让事件面板下拉里出现该函数（`pageManager.ts:247-251`），这是第四个隐藏概念。

步骤数：5 步 + 至少 3 个开发者概念（componentId、find API、defineExpose）+ 全程手写代码。

### C.2 任务 2：勾选复选框 C 时显示字段 D

当前 UI 路径（设计器内唯一途径）：

1. 选中复选框 C → 切"事件"页 → `change` → ＋ → 动作配置弹窗。
2. 切"自定义函数" → Monaco 写：
   ```js
   function showD(e) {
     find('D的id').setAttr('hidden', !e);
   }
   defineExpose({ showD });
   ```
   （官方做法见 `disableDisplay/index.vue:90-91` 与 `customFunctions.md:12-18`）

认知障碍：

- 需要知道事件回调参数 `e` 就是 switch 的布尔值；需要知道 `setAttr('hidden', ...)` 对应 schema 的 `props.hidden`（`node.vue:262` 读 `innerSchema.props?.hidden`），即"隐藏"是 props 而非状态。
- 备选的 `fieldStates` 方案（`types/builder.ts:1-24`，condition 是函数）在**设计器里没有任何编辑入口**——用户要么写代码要么改宿主，界面走查走不通。
- 显示/隐藏联动与"禁用联动"是两套机制（setAttr vs fieldState），用户无法在界面上统一理解。

步骤数：5 步 + 写 JS + 理解 hidden props 语义；若想用"字段状态"方案则设计器内无入口。

### C.3 任务 3：点按钮 E 时提交表单并跳转

当前 UI 路径：

1. 选中按钮 E → 事件面板 → `click` → ＋。
2. 在动作弹窗左侧点"组件"→ 在组件树里找到 form（`aigenActionModal/index.vue:271-305`，树节点带"复制ID"按钮）→ 选"校验表单 validate"动作（`ui/antd/src/form/index.ts:6-19` 定义了 getData/setData/validate）。
3. 若还要"获取数据 + 跳转"：要么继续加动作（无内置跳转动作），要么切回"自定义函数"写 `find('form').validate()` + `window.location.href=...`，或者依赖宿主注册"公共函数"（`docs/guide/extensions/publicMethods.md:17-32`）——但"公共函数"列表里出现什么完全取决于宿主。
4. 参数若涉及表单值，需要手填 `{"__isExpression__":true,"content":"..."}` 之类的 JSON（`pageManager.ts:301-309`），普通用户无从得知。

认知障碍：

- "提交"不是一个动作而是动作链（validate → getData → 跳转），弹窗一次只能配一个动作，用户要往返弹窗多次。
- 跳转无内置能力，需宿主公共函数或写 JS——用户以为的低代码操作变成"找开发要公共方法"。
- 动作弹窗三栏布局（对象/动作选择/配置，`aigenActionModal/index.vue:251-372`）+ 动作三元组（type/methodName/args，30-37 行初始 `{componentId, methodName:'test', type:'custom'}`）概念负担重；默认 methodName 居然是 'test'，示例感极强。

**三个任务共同的心智成本**：全部需要"选中元素 → 事件面板 → 动作弹窗 → 自定义函数/Monaco"这条唯一通道；全程接触 componentId、生命周期术语（vnodeMounted 等，`event.vue:26-59`）、动作三元组、defineExpose、JSON args、**isExpression**、fieldStates 函数——**没有一项是面向业务用户的"配置"心智模型，全是开发心智模型**。

## D. 结论

### D.1 现有交互模型（"事件列表 + 大弹窗 + 树选目标"）的根本缺陷

1. **入口割裂、与画布零关联**：事件/关联的唯一入口是右侧"事件"侧栏（`rightSidebars/event/event.vue`）和 1200px 动作弹窗（`aigenActionModal/index.vue:244-250`）；画布上没有任何入口按钮（选中框操作栏只有父节点/复制/删除，`previewWidgets.vue:430-452`）。用户"看着画布"无法发起关联操作。
2. **无状态可视化**：画布元素没有任何"已绑定事件/规则/联动"标记；全库唯一的"事件"角标在左侧大纲树（`outline.vue:102-107`），且判断逻辑 `hasBoundEvents`（21-28）已存在却只服务大纲树——数据可用，UI 缺失，用户无从发现"谁绑了什么"。
3. **目标选择靠"树 + 复制 ID"，无方向性表达**：动作目标通过组件树点选（`aigenActionModal/index.vue:271-305`）或脚本里硬编码 componentId；没有画布上"源→目标"的点选/连线/箭头，也没有"目标元素反查谁引用了我"。
4. **跨元素逻辑 ≈ 写代码**：值联动、显隐、禁用全部走自定义函数 JS（`sum/index.vue:86-87`、`disableDisplay/index.vue:90-91`、`aigenScriptEdit.vue:26` 直改全局 script）；Monaco 编辑器 + defineExpose + find/setAttr API 把低代码降级为"在低代码工具里写原生 JS"。
5. **能力孤岛、协议私有**：公式引擎（`formulaEngine.ts:33-233`）、字段状态 condition（`types/builder.ts:14`）、事件总线（`useEventBus.md`）、表格元数据（`useTableMeta.ts:9-27`）全部存在但彼此孤立；公式只能经 `__isExpression__` 私有协议在动作参数里触发（`pageManager.ts:301-309`），字段状态只能由宿主传 `field-states`（`builder.vue:124-132`）——没有任何设计器 UI 把它们串起来。

### D.2 画布层缺失的能力（可作为后续迭代方向）

| 缺失能力 | 现状证据 | 建议方向 |
| --- | --- | --- |
