## 0. 现状与问题诊断（基于现有代码事实）

### 0.1 现状数据流（运行时）

```
组件 config.event / 硬编码 LIFECYCLE_EVENTS
        │  event.vue 组事件列表
        ▼
schema.on: { [event]: ActionsModel[] }        ← 类型见 packages/types/src/aigen-designer.ts:45-47
        │
        ▼  node.vue getProps（设计态不挂载事件，见 node.vue:369-380）
onXxx(...args) → pageManager.doActions(on[event], scopeName, ...args)
        │
        ▼  pageManager.ts doActions（260-337 行）
args JSON.parse → __isExpression__ 对象交给 FormulaEngine.calculate(content, {event, formData})
switch(type): component→实例方法 / custom→funcs / public→methodsMap
        │
        ▼  组件实例 exposed（node.vue:432-450 提供）
setValue / getValue（input 组件）/ setAttr / getAttr / schema
```

页面级生命周期：`aigenReady` 由 builder.vue triggerAigenReady（156-167 行）在全部组件挂载后遍历所有 schema 执行。

### 0.2 用户痛点 → 根因映射

| 用户原话（痛点） | 代码层面的根因 |
| --- | --- |
| "画布上不知道元素之间有没有关联" | 事件/动作只存在 `schema.on` 里，画布节点（nodes.vue / nodeItem.vue）零可视化标记；无"关联"概念 |
| "不知道如何快捷进行多元素间绑定" | 绑定入口只在右侧"事件"面板（event.vue）逐事件点加号；画布无点选式入口、无右键菜单增项 |
| "1200px 弹窗不友好，看不懂如何绑定、能做什么" | aigenActionModal 单屏堆叠"左树+动作列表+右配置"；无步骤、无向导、无方法说明、无画布联动、无搜索、无表达式插入器 |
| "生命周期事件名看不懂" | LIFECYCLE_EVENTS 直接暴露 vnodeMounted / vnodeErrorCaptured 等 Vue 术语（event.vue:26-59），无业务化命名 |
| "事件卡片信息太少" | AigenActionEditorItem 动作卡片只显示"组件label + methodName"，无摘要、无启停用、无复制（AigenActionEditorItem.vue:130-136） |
| "参数不会填" | aigenArgsEditor 按数组下标渲染（field 即下标），无表达式插入 UI——而运行时 doActions 已支持 `__isExpression__`（pageManager.ts:301-305），只是没有任何 UI 能生成它 |

### 0.3 可直接复用的存量能力（方案的红利）

- **表达式**：FormulaEngine（jsep，$formData/$event/$vars + SUM/IF/... 内置函数），运行时已就绪，缺 UI。
- **事件总线**：createEventBus('root')（builder.vue:120、designer.vue:91）+ useEventBus，跨组件 emit/on 已存在，缺设计态入口。
- **字段状态**：FieldStateMap（DISABLED/HIDE/READ/WRITE，builder.vue:124-132 由 host 的 fieldStates prop 注入），缺设计态编辑 UI。
- **设计态安全**：node.vue 在 isDesignMode 下不挂事件，设计画布操作不会误触发运行时行为——后续所有"预览"能力必须保持这一约定。
- **schema 驱动表单**：attribute.vue + attributeItem.vue 的 AigenNode 渲染器可复用于参数表单与联动编辑器。
- **扩展机制**：pluginManager.panel.registerRightSidebar（docs/guide/extensions/rightSidebar.md），新面板"关联与计算"以同样方式注册，天然兼容插件体系。

## A. 设计原则

1. **业务语言优先（Business Language First）** 所有用户可见文案用业务人话：事件叫"值变化时"而非 `change`，生命周期叫"页面加载完成"而非 `aigenReady`；技术名（Vue 事件名、方法名、字段 id）只在"高级/源码"模式展示，且始终伴随人话解释。

2. **画布即真相（Canvas is the Source of Truth）** 画布元素是事件/关联的**第一入口与可视化载体**：有绑定就有角标，参与联动就有关联标记；侧边栏任何选中都能在画布上高亮对应目标元素，双向同步。画布负责"在哪里、牵涉谁"，侧边栏负责"细节是什么"。

3. **从"绑定"到"行为流"（From Binding to Behavior Flow）** 用户的心智模型不是"给 change 事件挂一个回调"，而是"**当 A 发生时，让 B 做什么**"。所有界面按 事件(When) → 动作链(Then) 组织；动作摘要用"把『单价』设置为…"这样的句子呈现，而不是方法名堆砌。

4. **渐进披露（Progressive Disclosure）** 默认只暴露高频能力（赋值、显隐、禁用、调用方法）；脚本、条件、延迟、表达式、备注一律折叠进"更多/高级"。新手 30 秒能完成第一个绑定，专家不被折叠层挡住。

5. **每一步都可预览、可撤销、可安全返回（Safety & Reversibility）** 设计态永不触发运行时事件（沿用 isDesignMode 约定）；所有写入经 revoke 栈可撤销；向导每步可回跳，已填步骤打勾；删除/停用不丢数据（保留 schema，仅标记）。

## B. 交互方案分层设计

## B1 画布层：事件/关联状态可视化与"关联模式"

### B1.1 元素状态角标（设计态叠加层，仅设计模式渲染）

在 `nodeItem.vue` 渲染的每个节点外套一个绝对定位叠加层（`EventBadge.vue`），右上角显示：

| 角标 | 含义 | 规则 |
| --- | --- | --- |
| ⚡ N | 绑定了 N 个动作的事件 | N = 所有事件动作总数（含停用，停用计为灰色）；N>0 才显示 |
| 🔗 N | 参与 N 条"字段联动/计算"规则 | 源侧（影响别人）蓝色、目标侧（被别人影响）绿色、双向紫色，P3 引入 |
| 灰 ⚡ | 全部动作处于停用 | 角标置灰 + tooltip "存在停用的行为" |

- 角标 hover → tooltip 显示摘要：前 2 条动作人话摘要 + "共 N 个动作，X 个停用"。
- 角标点击 → 选中该元素并**自动切到"行为"侧边栏**、展开对应分组（画布与面板双向联动）。
- 徽标区域 `pointer-events: auto` 且 `stopPropagation`，不干扰拖拽/选中（与现有 data-aigen-id 机制共存）。

### B1.2 关联模式（Link Mode）

**入口（三处等价）**

1. 顶部工具栏新增"🔗 关联"开关按钮（快捷键 `L`），激活态高亮；
2. 元素右键菜单 → "建立关联…"（自动以该元素为源，进入模式）；
3. "行为"面板内动作向导步骤 2 的"画布点选"Tab（见 B3）。

**进入后的画布状态**

- 顶部浮动提示条（画布内侧居中顶部）： `[🔗 关联模式] ① 点击源元素 → ② 点击目标元素 → ③ 选择关联方式（Esc 退出）`
- 已有关联元素高亮描边：源=蓝、目标=绿、双向=紫（P3 才有）；无关联时仅提示。
- 关联模式下禁用画布拖拽排序（`editContainer/index.vue` 已持有 contextMenu 关闭逻辑，扩展一个"模式守卫"即可），避免误拖。

**点选流程（三步走，不用连线）**

```
1) 点源元素          → 源元素显示"选中环"（2px 主色描边 + 轻微脉冲）
2) 点目标元素        → 目标元素高亮；若目标不可关联（容器/纯展示）给出 toast 提示
3) 弹出"快速关联"气泡 QuickLinkPopover（锚定在目标元素旁）
   ┌─────────────────────────────┐
   │  🔗 建立关联  源:「数量」→ 目标:「金额」 │
   │  [值联动]  [显示/隐藏]  [禁用]   │
   │  [自定义事件…]          [取消]   │
   └─────────────────────────────┘
   点「值联动」→ 进入 B4 联动编辑器（源/目标已预填）
   点「自定义事件…」→ 进入 B3 动作向导（步骤 1 预选"操作组件"，步骤 2 预填目标）
```

**退出**：Esc / 再点工具栏按钮 / 点击画布空白 / 完成一次关联（默认退出，设置里可改为"保持模式"）。

**为什么不画连线**：见 E-1。

### B1.3 右键菜单增项

现有右键菜单（contextMenu 注入，nodes.vue:137）在"复制/删除/锁定…"基础上追加：

- **绑定事件…** → 打开 B3 动作向导（预选当前元素为"源"，动作类型默认"操作组件"）
- **建立关联…** → 进入关联模式，当前元素预选为源
- **查看已绑定行为** → 切到"行为"侧边栏并展开该元素事件分组
- （多选时）**批量绑定事件…**、**批量启停用** → 见 B1.4

### B1.4 多选与批量行为（P2 尾期，小步引入）

- **进入多选**：`Shift+点击` 追加选中（designer.state 增加 selectedNodes 集合，现有 matched 是面包屑祖先链，不可复用，需新增）。
- **批量能力（仅"安全动作集"）**：批量追加同一动作（仅允许 `component.setAttr`、`component.setValue`、启停用、删除），不开放任意方法批量绑定（防误操作，见 E-7）。
- 批量操作通过同一 B3 向导完成，步骤 2 显示"已选 N 个元素"。

## B2 事件面板层：重设计的"行为/事件"侧边栏

### B2.1 定位与命名

- 侧边栏标题由"事件"改为 **"行为"**（副标题 tooltip："元素能响应什么、要做什么——即事件与动作链"）。
- 事件分组**业务化命名** + 每组分一句解释文案（首次打开默认展开"组件事件"与"页面级生命周期"，其余折叠）。

### B2.2 面板结构（自上而下）

```
┌─────────────────────────────────┐
│ 🔍 搜索（事件名/动作摘要/目标组件名）    │
├─────────────────────────────────┤
│ ⚡ 组件事件（该组件可响应的操作）        │  ← 来自 config.event
│   ▼ 值变化时  change                │
│   │  （值改变后触发）                │
│   │  [1] 把「金额」设置为 数量×单价 ✓  │  ← 动作行（含摘要、启停用、编辑/复制/删）
│   │  [2] 调用「合计」的 计算合计    ✕  │  ← 灰色=停用
│   │  [+ 添加动作]                  │
│   ▼ 点击时   click                  │
├─────────────────────────────────┤
│ 📦 页面级生命周期                    │
│   ▼ 页面加载完成  aigenReady         │
│   │  （整个页面渲染完成后触发一次）     │
├─────────────────────────────────┤
│ 🧩 组件级生命周期                    │
│   ▼ 挂载 / 更新 / 卸载 / 错误        │  ← 子分组，人话命名见 B5
├─────────────────────────────────┤
│ 🔗 关联与计算（本元素参与的联动）       │  ← 只读入口，点击跳 B4 面板
│   [2] 规则：数量变化 → 金额=数量×单价   │
└─────────────────────────────────┘
```

### B2.3 事件卡片与动作行能力

- **事件卡片**：名称（人话）+ 描述（1 行解释，hover/展开看完整）+ 右侧：动作数徽标 + 事件级启停用 switch + 展开箭头。事件级停用 = 该事件全部动作不执行（写入 `schema.on` 的 enabled 由动作级归一化，事件级用元数据或全部动作 enabled=false）。
- **动作行**：
  - 拖拽把手（保留 VueDraggable 排序，同时提供 ↑/↓ 按钮满足键盘/无障碍）；
  - 启停用圆点/switch（新增）；
  - **动作摘要**（新组件 `ActionSummary` 统一生成）：
    - component → "调用「{目标组件label}」的 {方法人话名}"
    - component + setValue/setAttr → "把「{目标label}」设置为 {值摘要}"
    - custom → "执行自定义函数 {funcName}"
    - public → "执行 {publicMethod.description}"
  - 操作：编辑 ✎ / 复制 ⧉ / 删除 🗑 / 更多（条件、延迟、备注 → 高级折叠，P1 仅保存字段，P3 生效）。
- **复制**：复制动作生成新 id（ActionsModel 需新增 id，见 C），可粘贴到本元素其他事件或剪贴板跨元素粘贴（P1 仅本元素内）。
- **空状态引导**（元素一个动作都没有时）：
  ```
  ┌──────────────────────────────┐
  │  (插图: 元素 + 闪电)           │
  │  让这个元素"动"起来             │
  │  [点击时显示/隐藏其他元素]       │
  │  [值变化时计算合计]             │
  │  [页面加载时填充默认值]          │
  └──────────────────────────────┘
  点击任一模板 → 直达 B3 向导并预填
  ```

## B4 新增"关联与计算"面板（link_view）

### B4.1 定位

独立右侧边栏"**关联与计算**"（id: `link_view`，按 docs/guide/extensions/rightSidebar.md 的机制注册，sort=250 位于属性/样式之间或之后），B2 面板底部提供跳转入口。三个子模块：

```
│ │    → 设置「金额」= 数量 × 单价     [✓][✎][🗑]│  │
│ └──────────────────────────────────────┘  │
│ 新建/编辑弹层（小 Modal 或抽屉内联展开）:      │
│   源: [字段/元素 ▼] 触发时机:[值变化时▼]      │
│   条件: (可选) [if] 字段 [运算符] [值]        │
│   目标: [元素 ▼]  行为: [显示|隐藏|禁用|赋值|清空▼]│
│   赋值内容: [常量 | 字段引用 | 公式] + [fx]    │
└──────────────────────────────────────────┘
```

- 行为映射（全部落到现有运行时能力）：| 行为 | 运行时落点 | | --- | --- | | 显示/隐藏 | 目标 `setAttr('hidden', false/true)`（或 P3 走 fieldState HIDE） | | 禁用/只读 | `setAttr('disabled'/'readonly', true)`（或 fieldState DISABLED/READ） | | 赋值 | `setValue(值/表达式)`（表达式经 `__isExpression__`） | | 清空 | `setValue('')` |
- **数据模型双写策略**（关键决策）：
  - **运行时模型** = 编译产物：源元素 `on[change]` 追加对应 ActionsModel（复用 doActions，**不新增运行时机制**）；
  - **设计态视图模型** = `schema.links: FieldLink[]`（描述 源/目标/行为/值/条件/启停用 的结构化元数据），面板读它渲染、改它保存，保存时**编译**到 `on[change]`；
  - 好处：可视化"关联视图"不依赖运行时改造；运行时零风险；旧数据无 links 时从 `on` 反解析（尽力而为，或提示"转为可视化规则"）。
- 校验：目标元素必须存在且可写；条件 DSL 用对象（`{field, operator, value}` 数组 + AND/OR），不做可视化 if/else 流程图（见 E-2）。

### B4.4 事件总线 / 全局状态入口

## B5 生命周期绑定重设计：人话化命名表

分组两级：**页面级生命周期**（1 个）与 **组件级生命周期**（7 个，按 挂载/更新/卸载/错误 子分组）。每个事件在面板中显示：新名称 + 解释 + 触发时机（tooltip），"高级"模式显示旧技术名。

| 旧事件名（技术名） | 新名称 | 解释（人话） | 触发时机 | 典型用途 | 示例 |
| --- | --- | --- | --- | --- | --- |
| `aigenReady` | **页面加载完成** | 整个页面所有组件都渲染完成后触发一次 | 首屏全部组件挂载后（builder.vue handleReady） | 初始化默认值、拉取首屏数据、初始跳转 | "页面加载完成后，把『日期』设为今天" |
| `vnodeMounted` | **组件挂载完成** | 当前组件完成首次渲染后触发 | 组件挂载后 | 组件自身初始化、加载选项数据 | "下拉框挂载完成后，加载选项数据" |
| `vnodeBeforeMount` | **组件挂载前** | 当前组件即将渲染到页面之前 | 渲染前一刻 | 预置初始属性/状态 | "挂载前先设置默认选中项" |
| `vnodeUpdated` | **组件更新完成** | 当前组件的属性或数据更新之后触发 | 每次更新后 | 值变化的后续处理（简单场景建议优先用对应业务事件，如 change） | "数据更新后刷新合计" |

| `vnodeUnmounted` | **组件卸载完成** | 组件从页面移除后触发 | 销毁后 | 清理定时器、解绑订阅 | "卸载时清理定时器" |
| `vnodeBeforeUnmount` | **组件卸载前** | 组件即将被移除之前 | 销毁前 | 释放资源、确认离开 | "卸载前提交未保存的数据" |
| `vnodeErrorCaptured` | **组件错误捕获** | 组件内部渲染或运行出错时触发 | 出错时 | 错误提示、降级显示 | "出错时提示『加载失败』并隐藏组件" |

## C. 数据模型演进建议

### C.1 ActionsModel 演进（types/src/aigen-designer.ts:9-14）

```ts
export interface ActionsModel {
  /** 稳定身份：拖拽 key、复制、条件引用、日志定位（旧数据缺省，读取层补 UUID） */
  id?: string;
  /** 动作命名（人话，用于摘要/搜索/下拉展示），可选 */
  name?: string;
  /** 备注，可选 */
  remark?: string;
  /** 启停用，缺省 true（undefined 视为启用，兼容旧数据） */
  enabled?: boolean;
  /** 动作分组名（行为流分组），可选，P1 先存字段 P3 生效 */
  group?: string;
  /** 延迟执行毫秒数，可选，运行时 P3 生效 */
  delay?: number;
  /** 条件（DSL 对象而非函数——函数不可序列化），可选，运行时 P3 生效 */
  condition?: ConditionGroup;
  type: 'component' | 'custom' | 'public';
  componentId?: string | null;
  methodName: string;
  /** JSON 数组字符串；元素可为 { __isExpression__, content }（现有支持，P1 补 UI） */
  args?: string;
}

export interface ConditionGroup {
  logic: 'AND' | 'OR';
  items: Array<
    | {
        field: string;
        operator: '==' | '!=' | '>' | '>=' | '<' | '<=' | 'in' | 'empty';
        value?: unknown;
      }
    | ConditionGroup
  >;
}
```

- 是否足够？**不够**。动作命名/备注/启停用/延迟/条件是高频业务诉求（"临时停掉这个联动排查问题"、"延迟 300ms 再刷新"），而现有模型完全无法表达；动作分组支撑"行为流"叙事。全部做成**可选字段 + 缺省兼容**，不动现有字段语义。

### C.2 schema.on 兼容旧数据策略

- 读取层归一化（新工具函数 `normalizeAction`，放 utils）：
  - 缺 `id` → 补 UUID（同时解决现有 VueDraggable `item-key="id"` 在无 id 时的潜在告警，AigenActionEditorItem.vue:121）；
  - `enabled === undefined` → 视为 true；
  - 其余字段透传，**不迁移、不重写**旧 schema（保存时才增量补齐 id）。
- 写入层保持现有 `on` 结构不变：`{[event]: ActionsModel[]}` 不改成 map，避免破坏所有既有组件/文档/宿主集成。
- 运行时兜底（P3）：doActions 对 `enabled === false` 跳过、`delay` 用 setTimeout、`condition` 求值异常时跳过该动作（fail-safe，延续现有"单动作异常不中断链"约定 pageManager.ts:274-287）。

## E. 明确"不做"清单

| # | 不做 | 理由 |
| --- | --- | --- |
| 1 | **画布节点连线图**（端口拖拽拉线、永久连线/曲线） | ① 画布元素是真实表单渲染，没有"端口"语义，连线视觉噪声大、维护成本高；② 键盘/读屏/移动端不可用；③ "点选源→目标→气泡"已覆盖 90% 场景且零学习成本。替代方案：角标 + 关联模式高亮 + 快速关联气泡。 |
| 2 | **可视化流程编排引擎**（BPMN/状态机/拖拽画布式 if-else 图） | 超出表单设计器边界：需要图引擎、执行器、序列化协议，与"表单即 JSON"的模型冲突；条件用简单 DSL 表单（字段/运算符/值）表达足够，复杂度可控。 |
| 3 | **运行时连线/状态常驻画布** | 设计态保持"轻标记"（角标/高亮），不渲染真实状态到画布，避免干扰布局与拖拽；运行态表现由宿主预览承担。 |
| 4 | **第四种"动作语言"** | 自定义函数继续用 JS（new Function，现有 setMethods），条件/表达式用 FormulaEngine DSL；不引入新脚本方言，减少认知与维护成本。 |
| 5 | **跨页面/跨表单编排** | 事件总线限定页面内（现有 createEventBus 'root' 通道）；跨页面状态与导航由宿主应用负责，设计器不越权。 |
| 6 | **组件间属性实时双向同步**（A.prop ≡ B.prop 的 live 绑定） | 双向同步易产生循环依赖与难以调试的隐式传播；统一用"事件驱动单向赋值"表达，语义清晰、可撤销。 |
| 7 | **任意方法的批量绑定** | 多选批量仅开放"安全动作集"（setValue/setAttr/启停用/删除），防止误操作波及多个元素。 |
| 8 | **全量事件调试日志面板** | P 系列不引入常驻调试 UI；用现有 console 输出 + 预览模式验证，后续如需再单独立项。 |
