## 5. 遗留问题与建议

### 5.2 文档与实现的小出入（建议修正，非阻塞）

1. `docs/guide/action/behavior.md:29` 宣称动作卡片「同时提供 ↑/↓ 按钮」，实现仅有拖拽把手（VueDraggable），无 ↑/↓ 按钮。
2. `behavior.md:32` 宣称「删除需确认」，`handleDelete`（AigenActionEditorItem.vue:61-70）直接删除，无确认弹窗。
3. `behavior.md:32` 宣称复制「P1 支持在本元素内粘贴到其他事件」，实现为复制后追加到**同一事件列表**末尾（handleCopy :88-96），无跨事件粘贴 UI。
4. `AigenActionEditor/index.vue:32` 存在未使用变量 `const aigenActionDrawer = pluginManager.component.get('aigenActionDrawer')`（与基线 modal 写法同构，无副作用；typecheck/eslint 均不报，可保留或删除）。

### 5.3 已知风险 / 观察

1. **拖拽排序写回链**：VueDraggable 直接绑定 `props.events[item.type]`（基线同款写法），排序以数组原地变更生效，但不经 update:modelValue → revoke 栈（排序不入撤销历史）。属既有行为，未在本波引入。
2. **事件级开关语义**：任一动作 enabled=false 时事件级开关显示为关；再点开会把该事件**全部**动作置为启用（覆盖原有停用项）。符合「事件级」语义，但与动作级开关混用时会互相覆盖，建议后续在产品文案上提示。
3. **2>&1 退出码噪音**：PowerShell 重定向下 pnpm stderr（Vue/element-plus 告警）会令 vitest/vite 显示 exit 1，实际全部通过/构建成功；CI 环境（非 PowerShell）不受影响。
4. **1200px 旧弹窗仍可被旧宿主通过 get('aigenActionModal') 调用**，且其 index.vue:33 残留 `methodName: 'test'` 默认值（04 报告已标注的技术债），不在本波清理范围。

### 5.4 P2 / P3 衔接点

- **P2（画布关联模式）**：StepTarget 的画布点选（data-aigen-id + findInstance.exposed.schema + 高亮/防误触）可直接抽取为 useLinkMode 的「选目标」阶段复用；角标/关联模式不依赖本次改动。
- **P3（运行时增强）**：ActionsModel 新增字段（enabled/delay/condition/group）已存储，doActions（pageManager.ts:260-337）按计划保持 fail-safe 未动；P3 在 doActions 增加 `enabled===false 跳过 / delay setTimeout / condition 求值` 时，需注意读取层 normalizeAction 的 enabled 缺省 true 语义与其一致。
